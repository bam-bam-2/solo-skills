# 네이버 정보성(하우투) 글쓰기 — 사용자 블로그

목표: 검색으로 들어온 사람이 **그 자리에서 문제를 해결하고 나가게** 만드는 글. 후기도 서사도 아니고, 단계별 안내가 본체다.

근거 파일: `references/naver-search-facts.md` — 네이버 공식 문서에서 확인된 것과, 실측 데이터, 그리고 **쓰면 안 되는 카더라 수치**가 정리돼 있다. 수치를 인용하기 전에 반드시 이 파일을 확인한다.

## 0. 이 스킬을 쓰는 경우

- "○○ 하는 법", "○○ 안 될 때", "○○ 무료로 하는 방법" 류
- 사용자가 만든 도구(내가 만든 도구)를 자연스럽게 쓰이게 하는 글
- 여행·공간 후기 → `naver-travel-post` / 기획 노트·강연 후기 → `naver-branding-post`

이 블로그의 주 카테고리는 커뮤니티·워크숍·여행이다. 정보성 글을 마구 늘리면 C-Rank의 "일관된 주제"(네이버 공식 5대 원칙 중 2번, 전체의 50% 이상이 핵심 주제)를 깬다.
→ **정보성 글은 월 2~4편을 상한으로 본다.** 그 이상 필요하면 별도 계정을 검토하되, 계정 분리는 사용자가 이미 한 번 거절한 사안이니 먼저 물어본다.

## 1. 쓰기 전에 반드시 측정한다

추측으로 쓰지 않는다. 순서:

1. **키워드를 정하고 네이버 블로그탭에서 실제로 검색한다** (`https://search.naver.com/search.naver?ssc=tab.blog.all&query=키워드`)
2. 상위 5~7개 글을 **직접 열어서** 글자수·이미지 수·동영상·외부링크·태그를 잰다.
   측정 코드는 `references/naver-search-facts.md` D절 참고. **`document.querySelectorAll('img')`로 세지 말 것** — UI 아이콘까지 잡혀서 터무니없는 수가 나온다
3. 상위 글들이 **공통으로 다루는 것**과 **아무도 안 다루는 것**을 적는다. 빈틈이 이 글의 존재 이유가 된다
4. 발행 직전 상태(최근 글의 발행일)를 보고 이 키워드가 아직 살아있는지 확인한다. 상위 글이 다 1년 전이면 수요가 죽은 키워드다

측정값이 기존에 적어둔 기준과 다르면 **측정값을 따르고, 근거 파일을 갱신한다.**

## 2. 키워드와 제목

- 롱테일로 간다. 이 블로그는 IT/도구 주제의 C-Rank가 없다
- 제목 **앞쪽에 핵심 키워드**를 둔다. 상위 글들이 전부 그렇게 하고 있다
- 제목은 화면에 실제로 있는 동작으로 쓴다. "완벽 가이드", "총정리", "꿀팁 Zip" 같은 어그로는 금지(네이버가 낚시성 제목을 스팸으로 명시)
- 제목에 쓴 단어는 본문에서 실제로 다뤄야 한다
- 키워드 반복은 자연스러운 선에서. 네이버가 **키워드 남용을 스팸으로 명시**했다

## 3. 분량과 이미지 (실측 기준)

2026-08-08 "카톡 캡처 모자이크" 상위 7개 실측:

| 항목 | 기준 |
|---|---|
| 글자수(공백 제외) | **1,200~1,800자.** 중앙값 1,306자. 2,000자 넘길 필요 없다 |
| 본문 이미지 | **15~25장.** 중앙값 22장 — 글자보다 이미지가 본체다 |
| 동영상 | 상위 7개 중 1개만 있음. 넣으면 차별화되지만 노출 이득은 미확인 |
| 외부 사이트 링크 | 상위 **전부 0개**. 랭킹에 도움 안 된다 |
| 태그 | 3~5개 |

**이미지 규칙**
- 단계마다 스크린샷 1장이 원칙. "여기를 누른다"는 문장 옆에 그 화면이 있어야 한다
- 스크린샷은 **직접 찍은 것**만. 스톡 이미지·남의 블로그 캡처 금지
- 화면 안에 개인정보(이름·번호·계좌·주소)가 있으면 예시용 가짜 데이터로 바꿔서 다시 찍는다. 가릴 거면 가린 티가 나게 가린다
- 이미지에 화살표·번호 같은 주석을 얹으면 스캔이 쉬워진다. 브라우저 캔버스로 직접 합성하면 된다
- 업로드는 에디터 좌측 상단 **'사진' 버튼 → 파일 직접 선택**. 글감/외부이미지 삽입은 쓰지 않는다
- 유사한 컷을 여러 장 넣지 않는다 (네이버가 스마트블록 기준에서 "유사 이미지 중복 제외"를 언급)

## 4. 링크 — 자기 사이트로 보내는 글일 때

이게 이 스킬의 핵심이자 제일 위험한 부분이다.

- **링크는 랭킹을 올리지 않는다** (상위 글 전부 외부링크 0개). 링크의 목적은 오직 유입이다
- **본문 안 링크는 1~2개.** 그 이상은 네이버가 명시한 "링크 스팸"에 가까워진다
- 링크를 거는 위치는 **독자가 실제로 그 도구를 열어야 하는 순간** 딱 한 번. 도입부와 마무리에 반복해서 박지 않는다
- 자기가 만든 도구라는 사실을 숨기지 않는다. "제가 만들어 쓰고 있는" 한 줄이 오히려 D.I.A.의 경험 정보 신호가 된다. 다만 자랑으로 흐르지 않게 한 문장으로 끝낸다
- **글 전체가 도구 홍보로 읽히면 안 된다.** 도구를 안 쓰는 방법(앱 자체 기능 등)을 먼저 정직하게 소개하고, 그게 안 되는 상황을 짚은 다음 도구를 꺼낸다. 이 순서를 지키면 글이 광고가 아니라 안내가 된다
- 대가성·협찬이 아니면 대가성 문구는 필요 없다. 단 도구 페이지에 제휴 배너(쿠팡파트너스 등)가 있으면 **그 페이지에 고지 문구가 살아 있는지** 확인한다

## 5. 구조 템플릿

```
1. 도입 3~4줄
   - 인사말 없이 상황으로 시작 ("PC로 캡처한 이미지는 카톡 익명 캡처가 안 먹힙니다.")
   - 이 글에서 알 수 있는 것 예고
2. 상황 정리 (표 1개)
   - 어떤 경우에 어떤 방법을 쓰면 되는지 한눈에
3. 방법 1 — 앱 자체 기능 (가장 쉬운 것부터, 스크린샷)
   - 되는 조건과 안 되는 조건을 명확히
4. 방법 2 — 안 될 때 쓰는 방법 (여기서 도구 등장, 스크린샷 단계별)
   - 링크 1개
5. 실제로 해본 결과 / 주의할 점
   - 모자이크가 복원될 수 있는 경우 같은 실질적 경고
6. 마무리 2~3줄 + 태그 3~5개
```

## 6. 톤 (3개 네이버 스킬 공통)

- 존댓말, 담백하게. 사실 중심 문장 + 가끔 가벼운 감상 한 줄
- 이모지 0~3개
- 금지 패턴:
  - "~이 아니라 ~이다" 대조 구문 (반전은 "아닙니다." 처럼 문장을 끊어서)
  - "여정", "굴러가다", "~자리", "진짜 기준" 같은 은유
  - 안심시키기용 문장 ("걱정 안 하셔도 돼요", "절대 ~하지 않아요")
  - "완벽 가이드", "총정리" 같은 어그로 제목
- 정보성 글은 특히 **지시문이 명확해야 한다.** "~하시면 됩니다"보다 "왼쪽 위 사진 버튼을 누릅니다"

## 7. 절대 넣지 않는 것

- 전세자금 등 개인 재무 정보, 사업 계약 금액
- 클라이언트·멤버 실명, 연락처, 계좌번호, 사업자번호 — 과거 글에 나왔어도 이번에 또 써도 되는지 매번 확인
- 예시 스크린샷 속 실제 대화·실명·실제 번호. 전부 지어낸 값으로 다시 찍는다
- 근거 없는 숫자. 근거 파일 B절의 카더라 수치들

## 8. 작업 순서

1. 키워드 확정 → 1절대로 상위 글 실측
2. 빈틈 확정 → 이 글이 뭘 더 주는지 한 문장으로 적고 시작
3. 스크린샷 촬영·합성 (가짜 예시 데이터로)
4. 초안 작성 → **채팅으로 보여주고 승인받는다** (발행 전 필수)
5. 발행: blog.naver.com 글쓰기(스마트에디터) → 본문 → 사진 업로드 → 동영상(있으면) → 카테고리 → 태그 → 발행
6. 발행 후 **네이버 서치어드바이저에서 해당 URL 수집 요청**을 넣는다 (정보성 글은 색인 속도가 유입 속도다)
7. 발행 URL 보고. 발행 후 2~3일 지난 글은 수정하지 않는다 (미노출 위험 — 고칠 게 있으면 새 글)

## 9. 티스토리 동시 운영

사용자가 네이버 정보성 글 발행을 요청하면 같은 승인 건 안에서 티스토리 동반 글도 준비한다.

- 티스토리: `https://bam-bam-2.tistory.com/`, 블로그명 `커뮤니티 콘텐츠 기획자 사용자`. 사용자가라는 사람의 여러 작업을 담는 개인 브랜드 블로그이며 도구 전용 블로그가 아니다.
- 정보성 글의 카테고리는 `웹 도구 사용법`을 쓴다. 이 카테고리는 커뮤니티 기획·워크숍·공간 답사·개인 서사와 나란히 놓인 콘텐츠 축 하나다.
- 네이버 원고를 그대로 복제하지 않는다. 같은 키워드 조사와 직접 제작 이미지를 쓰되 구글 검색 의도에 맞춰 제목, 도입, 소제목, FAQ를 새로 쓴다.
- 네이버는 검색 유입과 실제 사용 안내가 목적이다. 티스토리는 설치 여부, OS별 단축키, 비교, FAQ처럼 구글에서 독립적으로 답이 되는 구조를 우선한다.
- 제목 앞쪽에 핵심 검색어를 두고 H2/H3 구조를 사용한다. 첫 문단은 검색 결과에 쓰일 수 있도록 2~4문장으로 요약한다.
- 이미지마다 실제 화면을 설명하는 대체 텍스트를 넣는다. 같은 이미지라도 문맥에 맞는 설명을 쓴다.
- 내 도구 링크는 해당 도구를 다루는 글에서만 독자가 도구를 여는 지점과 마무리 중 최대 2곳에 둔다. 다른 소재의 글에 관성적으로 넣지 않는다.
- 네이버와 티스토리의 초안을 함께 보여주고 한 번 승인받은 뒤 각각 발행한다. 네이버만 또는 티스토리만 발행하라는 요청이 있으면 그 범위를 따른다.
- 발행 뒤 네이버는 네이버 서치어드바이저, 티스토리는 Google Search Console에서 해당 URL 색인 요청 상태를 확인한다.
- 티스토리 글에도 근거 없는 애드센스 승인 글 개수, 기간, 수익 수치를 넣지 않는다.

## 10. 발행 후 확인

- 3~7일 뒤 해당 키워드로 검색해서 몇 위인지, 스마트블록 어디에 잡혔는지 본다
- 도구로 유입이 실제로 생겼는지는 GA4 추천(Referral) 소스에서 `blog.naver.com`을 본다
- 안 잡히면 글을 고치지 말고 **다음 글에서 각도를 바꾼다**
